# Setup and Roadmap

*The rest of this compendium teaches how and why machine learning works; this chapter is about doing it on real data with real tools. It sets up a modest laptop for ML engineering work, explains how datasets are handled, and organises the hands-on work into three levels (foundations, production, frontier), each with a reading order, project milestones placed at the end of the chapters they apply, and a clear finishing line*

- Reading about cross-validation is not the same as discovering that your own model leaked the test set. The milestones turn each relevant chapter into practice: **learn** the idea in the chapter, **do** it on the project, then **do it better** in a later milestone once you know more.

- Milestones appear only where a project step fits naturally. Chapters that are mostly theory (learning theory, probabilistic graphical models, most of the maths chapters) have none; their payoff is understanding why the practical steps work.

## What You Need

- A Linux laptop with an SSD and 8-16 GB of RAM is enough for everything except fine-tuning neural networks. A free GPU notebook (Google Colab or Kaggle) covers that.

| Work | Laptop (CPU, 12 GB RAM) | Free GPU notebook |
|---|---|---|
| pandas, scikit-learn, gradient boosting on tabular data | yes | not needed |
| SQL with DuckDB, small data pipelines, Spark in local mode | yes | not needed |
| MLflow, DVC, FastAPI, Docker, monitoring | yes | not needed |
| PyTorch with small models and datasets | yes, slower | faster |
| Fine-tuning transformers | no | yes |

- With 12 GB of RAM, run one heavy tool at a time: an Airflow scheduler, a Spark session and a training job together will push the machine into swap.

## Setting Up

- Create one Python environment for the projects. `uv` is fast and handles Python versions; plain `venv` works too.

```bash
# with uv (https://docs.astral.sh/uv/)
uv venv ~/venvs/ml --python 3.12
source ~/venvs/ml/bin/activate
uv pip install numpy pandas scikit-learn matplotlib jupyterlab

# or with the standard library
python3 -m venv ~/venvs/ml && source ~/venvs/ml/bin/activate
pip install numpy pandas scikit-learn matplotlib jupyterlab
```

- Later milestones add packages as they need them (MLflow, FastAPI, PyTorch and so on); each milestone lists its installs. Install the CPU build of PyTorch on the laptop, which is much smaller than the default.

- Install Docker for the serving milestones (`sudo apt install docker.io` on Debian or Ubuntu, then add yourself to the `docker` group), and Git if it is not already there.

- Keep the projects in their own Git repository, separate from this compendium: one folder per project, code in `src/`, notebooks in `notebooks/`, and a `README.md` recording what each milestone changed and what the scores were. That log of decisions and results is what you will talk through in interviews.

## Data: Downloaded in Code, Never Committed

- Datasets are not stored in Git: they bloat a repository permanently, and many licences do not allow redistribution. Each milestone downloads its data in one line from a stable public source and caches it locally, so only the first run needs the internet.

- **Tabular project: Adult income.** About 49,000 people from the 1994 US census, with the task of predicting whether income exceeds 50,000 dollars. It is small enough for any laptop and has the problems real data has: missing values, categorical columns, a skewed target (about a quarter earn more than 50,000 dollars), heavy-tailed numbers, and sensitive attributes (sex, race) that the fairness milestone audits.

```py
from sklearn.datasets import fetch_openml
raw = fetch_openml("adult", version=2, as_frame=True, data_home="~/ml-data").frame   # cached after the first run
```

- **Text project: news or review classification.** AG News (120,000 news headlines in four topics) or IMDB (50,000 movie reviews, positive or negative), loaded with Hugging Face `datasets` (`pip install datasets`):

```py
from datasets import load_dataset
ds = load_dataset("ag_news")      # or load_dataset("imdb"); cached in ~/.cache/huggingface
```

- Milestone code is marked to run on your machine rather than in the browser, because it downloads data and, later, starts servers and containers.

## The Roadmap: Three Levels

- The compendium is large, so the projects are organised into three levels. Each level has a reading list, milestones that apply it, a clear finishing line, and something to show for it. Finish a level before starting the next; stop at whichever level matches your goal.

| Level | Goal | What it qualifies you for |
|---|---|---|
| **1. Foundations** | Take messy data to a trustworthy, well-evaluated, explained model | Junior and applied ML, data science roles: "this person knows ML" |
| **2. Production** | Run that model as a real service, and work with neural networks and language models | ML engineer roles in industry: "this person can ship ML" |
| **3. Frontier** | Build, scale and post-train language models and evaluate LLM systems | Research engineering and frontier-lab roles: "this person can build what the labs build" |

- Alongside every level, practise coding interviews with chapter 14 (data structures and algorithms) a little each week; every ML engineer interview includes a coding round.

## How to Work Through a Milestone

1. Read the chapter first; the milestone assumes it.
2. Run the milestone code as it is and check that your numbers look like what the text says to expect.
3. Commit, and write down the scores in your project README.
4. Try the "make it better" ideas at the end of the milestone and keep a change only if the cross-validated score really moves.
5. Never tune on the test set: it is held out in milestone 1 and used once, at the end.
