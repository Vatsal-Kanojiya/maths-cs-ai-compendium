# Neuromorphic Computing

*The brain runs on about 20 watts; training and serving large neural networks takes megawatts. Neuromorphic computing borrows the brain's design principles (spikes, local memory, event-driven computation) to build hardware and algorithms that compute with far less energy. This file covers spiking neuron models, how information is coded in spikes, learning with spike-timing-dependent plasticity and with surrogate gradients, neuromorphic chips, event cameras, an honest energy accounting, and where the approach does and does not pay off*

- Artificial neural networks were inspired by the brain, but the resemblance is loose. A GPU running a transformer computes with dense, synchronous, high-precision arithmetic, shuttling weights between memory and processors billions of times per second. A biological neuron communicates with sparse, all-or-nothing **spikes**, computes only when spikes arrive, and stores its "weights" (synapses) right where they are used. The brain's roughly 86 billion neurons run on about the power of a light bulb.

- **Neuromorphic computing**, a term coined by Carver Mead in the 1980s, builds systems that adopt these principles. The motivation is energy: most of the energy in conventional computing goes into moving data, not arithmetic (chapter 16's hardware fundamentals), and neural networks move enormous amounts of data. Neuromorphic systems are aimed especially at the edge (sensors, wearables, robots and drones) where power is scarce and inputs arrive continuously.

## Spiking Neurons

- A biological neuron integrates electrical input in its **membrane potential**. When the potential crosses a threshold, it fires a brief **action potential** (a spike) and resets. Hodgkin and Huxley's 1952 model describes this with nonlinear differential equations for ion channels; it is accurate and expensive. Neuromorphic computing mostly uses simpler models.

- The **leaky integrate-and-fire (LIF)** neuron is the workhorse. Its membrane potential $V$ leaks towards a resting value and integrates input current $I$:

$$\tau \frac{dV}{dt} = -(V - V_{\text{rest}}) + R\, I(t)$$

- When $V$ reaches the threshold $V_{\text{th}}$, the neuron emits a spike and $V$ is reset, often followed by a short **refractory period** during which it cannot fire. In discrete time (as in simulations and digital chips) this becomes $V_{t+1} = \beta V_t + I_t$ with decay $\beta = e^{-\Delta t / \tau}$, plus a reset after each spike.

- For a constant input above threshold, the firing rate follows from solving the equation:

$$f(I) = \left(t_{\text{ref}} + \tau \ln \frac{RI}{RI - V_{\text{th}}}\right)^{-1}$$

- zero below threshold, rising steeply above it, and capped at $1/t_{\text{ref}}$. The first coding task simulates an LIF neuron and matches this curve. Richer models add spike-frequency adaptation or bursting (the Izhikevich model reproduces many biological firing patterns with two equations), and many neuromorphic chips let the model be configured.

- **Synapses** connect neurons with weights, and spikes are carried to their targets after a delay. A spike is a binary event, so a synaptic weight is simply *added* to the target's potential when a spike arrives: no multiplication is needed, which matters for energy.

## Coding Information in Spikes

- How do spikes carry numbers? Several schemes coexist in biology and in engineered systems:
    - **Rate coding**: the value is the firing rate over a time window. Robust and simple, but slow (you must count spikes for a while) and not sparse for large values.
    - **Temporal coding**: the value is in spike timing, for example the time to the first spike after a stimulus (strong inputs fire first). Very sparse (one spike per neuron can suffice) and fast, but sensitive to timing noise.
    - **Population coding**: many neurons with overlapping tuning curves together represent a value, as in the Gaussian receptive fields used to encode inputs in the third coding task.

- The choice trades latency, energy and robustness, and it determines how many **time steps** a spiking network needs, which turns out to be central to whether it saves energy at all.

## Learning in Spiking Networks

- **Spike-timing-dependent plasticity (STDP)**, observed in biological synapses in the late 1990s (Markram and colleagues; Bi and Poo), is a local learning rule: if an input spike arrives shortly *before* the neuron fires, the synapse is strengthened (it helped cause the spike); if it arrives shortly *after*, it is weakened. The weight change decays exponentially with the time difference:

$$\Delta w = \begin{cases} A_+ \, e^{-\Delta t / \tau_+} & \Delta t > 0 \\ -A_- \, e^{\Delta t / \tau_-} & \Delta t < 0 \end{cases}, \qquad \Delta t = t_{\text{post}} - t_{\text{pre}}$$

- STDP needs only information available at the synapse, so it can run on-chip, continuously and cheaply. It performs a kind of unsupervised Hebbian learning ("cells that fire together wire together"). In the second coding task a neuron receiving 100 inputs learns, with no labels, to strengthen the 20 that fire in a repeating pattern and weaken the 80 that fire at random. Getting that selectivity needs competition, here a slightly stronger depression than potentiation; with balanced parameters every input drifts upwards. STDP alone has not matched backpropagation on complex supervised tasks.

- **Surrogate gradients** made spiking networks competitive. The spike is a step function, whose derivative is zero everywhere except at the threshold, where it is infinite, so backpropagation cannot pass through it. The surrogate-gradient method (popularised by Neftci, Mostafa and Zenke, 2019) keeps the true step in the forward pass but uses a smooth stand-in derivative in the backward pass, such as $\sigma'(v) = 1 / (1 + k|v - V_{\text{th}}|)^2$. The network is then unrolled over time steps and trained with **backpropagation through time** (chapter 07's RNNs work the same way; an LIF neuron is a recurrent unit with a threshold). The third coding task writes the forward and backward passes by hand and trains a spiking network to 99.8% accuracy on a toy problem, with hidden neurons spiking on fewer than one time step in five.

- **ANN-to-SNN conversion** trains an ordinary ReLU network and converts it, using the fact that an integrate-and-fire neuron's firing rate approximates a ReLU of its input. It reuses standard training but typically needs many time steps to reach the original accuracy, which erodes the energy benefit.

- Online learning rules that approximate backpropagation through time using only local, forward-in-time information (such as e-prop) aim to make learning on neuromorphic hardware both accurate and local.

- Spiking networks have reached accuracy close to conventional networks on image and audio benchmarks of moderate size, and spiking versions of transformers and language models exist as research systems, but at large scale they still lag, and training them is slower because of the time dimension.

## Neuromorphic Hardware

- Neuromorphic chips co-locate memory and computation in many small cores, each simulating a group of neurons with its synapses in local memory, communicating by sending spike packets over a network on chip. Computation happens only when spikes arrive (**event-driven**), so idle parts of the chip use almost no power.
    - **IBM TrueNorth** (2014): one million neurons and 256 million synapses on a chip consuming about 70 milliwatts for typical workloads.
    - **Intel Loihi** (2018) and **Loihi 2** (2021): programmable neuron models, on-chip learning rules, and up to about a million neurons per Loihi 2 chip. Intel's Hala Point system (2024) combines over a thousand Loihi 2 chips into a research system with over a billion neurons.
    - **SpiNNaker** (University of Manchester): a million ARM cores designed to simulate large spiking networks in biological real time, mainly for neuroscience; SpiNNaker2 adds machine learning acceleration.
    - **BrainScaleS** (Heidelberg): **analog** circuits that physically emulate neuron dynamics, running a thousand or more times faster than biology.

- Related approaches share the "keep memory next to compute" principle without spikes: **in-memory computing** with analog crossbar arrays (memristors or other resistive devices store weights as conductances, and Ohm's and Kirchhoff's laws compute matrix-vector products in place), and digital near-memory designs such as IBM's NorthPole (2023).

## Event Cameras

- A conventional camera samples every pixel at a fixed frame rate, whether or not anything changed. An **event camera** (dynamic vision sensor, Lichtsteiner, Posch and Delbruck, 2008) works like a retina: each pixel independently and asynchronously reports an event $(x, y, t, \text{polarity})$ when its log brightness changes by more than a threshold. The fifth coding task simulates one.

- Benefits: microsecond time resolution with no motion blur, very high dynamic range (above 120 dB, against about 60 dB for typical cameras, so it sees in dim light and bright sun at once), low latency and low power, and output proportional to how much is changing, so a static scene produces almost no data. In the simulation, a bar crossing a static textured scene generates around 6,000 events in 200 ms, against over 800,000 pixel readings for a 1,000 frame-per-second camera, and the parts of the scene the bar has not reached stay silent.

- Challenges: no absolute brightness (only changes), noise events, and the need for new algorithms, since most computer vision (chapter 08) assumes frames. Approaches include accumulating events into frames or "time surfaces" for conventional networks, graph networks over event point clouds, and spiking networks that consume events natively. Applications include high-speed robotics and drones, automotive sensing, eye tracking and industrial inspection.

## The Energy Question, Honestly

- Neuromorphic systems are often described as orders of magnitude more efficient, and sometimes are, but the comparison has conditions. The fourth coding task works through the arithmetic using widely quoted 45 nm energy figures (Horowitz, 2014): a 32-bit floating-point multiply-accumulate costs about 4.6 pJ, an addition (the cost of a spiking synapse) about 0.9 pJ.
    - A spiking network performs $p \times T$ synaptic additions per synapse per inference, where $p$ is the spike probability per time step and $T$ the number of time steps. On arithmetic alone it beats a conventional network only if $p \times T$ is below about 5. Sparse activity and few time steps are essential; rate-coded networks needing hundreds of steps lose.
    - **Data movement dominates both.** Reading a 32-bit weight from off-chip DRAM costs on the order of 640 pJ, over a hundred times the arithmetic. Keeping weights in local SRAM, next to the neurons, cuts total energy by two orders of magnitude, and this, as much as spiking itself, is where neuromorphic chips get their advantage.
    - On GPUs, which are optimised for dense matrix arithmetic, spiking networks typically gain nothing and run slower, because sparse, time-stepped computation maps poorly onto them.

- Fair comparisons measure the whole system, energy per inference at matched accuracy, on the same task, against a well-optimised conventional baseline (quantised and pruned, chapter 17), including memory and input/output. Under those conditions, neuromorphic systems show the clearest advantages for **sparse, temporal, always-on** workloads: keyword spotting and other audio wake-up tasks, gesture and event-camera vision, low-power sensor processing, closed-loop robotic control, and certain optimisation problems mapped onto networks of spiking neurons.

## Outlook

- Neuromorphic computing sits between neuroscience and engineering. It provides platforms for simulating brain circuits, and a design direction (event-driven, sparse, memory-local computation) that influences mainstream accelerators, which increasingly exploit sparsity and near-memory computing too. The main obstacles are the maturity of software tools, the difficulty of training spiking networks at scale, and the large ecosystem advantage of conventional deep learning hardware. Whether spiking networks will run large models efficiently, or whether their ideas will mainly be absorbed into conventional hardware, is an open question.

1. Simulate a leaky integrate-and-fire neuron, plot its membrane potential, and compare its simulated firing rate with the analytic f-I curve.
```python
import numpy as np
import matplotlib.pyplot as plt

# Leaky integrate-and-fire neuron:  tau dV/dt = -(V - V_rest) + R I(t);  spike and reset when V >= V_th
tau, R, V_rest, V_th, V_reset, t_ref = 20e-3, 1.0, 0.0, 1.0, 0.0, 2e-3      # seconds, arbitrary units
dt = 0.1e-3

def simulate(I, T=1.0, noise=0.0, seed=0):
    r = np.random.default_rng(seed)
    n = int(T / dt)
    V, refractory, spikes, trace = V_rest, 0.0, [], np.empty(n)
    for k in range(n):
        if refractory > 0:
            refractory -= dt; V = V_reset
        else:
            dV = (-(V - V_rest) + R * I) / tau * dt + noise * np.sqrt(dt) * r.standard_normal()
            V += dV
            if V >= V_th:
                spikes.append(k * dt); V = V_reset; refractory = t_ref
        trace[k] = V
    return np.array(spikes), trace

# 1. Membrane potential for a constant input
spikes, trace = simulate(1.5, T=0.2)
print(f"input 1.5: {len(spikes)} spikes in 200 ms")

# 2. Firing rate versus input current (the f-I curve), simulated and analytic
def analytic_rate(I):
    if R * I <= V_th: return 0.0                               # never reaches threshold
    return 1 / (t_ref + tau * np.log(R * I / (R * I - V_th)))
currents = np.linspace(0, 4, 21)
sim = [len(simulate(I)[0]) for I in currents]                  # spikes in 1 s = rate in Hz
print("input | simulated rate | analytic rate (Hz)")
for I, s in list(zip(currents, sim))[::4]:
    print(f"{I:5.1f} | {s:14d} | {analytic_rate(I):8.1f}")

fig, axes = plt.subplots(1, 2, figsize=(13, 4))
t = np.arange(len(trace)) * dt * 1000
axes[0].plot(t, trace, color='#3498db'); axes[0].axhline(V_th, color='#e74c3c', linestyle='--', label="threshold")
axes[0].set_xlabel("time (ms)"); axes[0].set_ylabel("membrane potential"); axes[0].legend()
axes[0].set_title("LIF neuron: integrate, fire, reset")
axes[1].plot(currents, sim, 'o', color='#3498db', label="simulated")
axes[1].plot(currents, [analytic_rate(I) for I in currents], color='#e74c3c', label="analytic")
axes[1].set_xlabel("input current"); axes[1].set_ylabel("firing rate (Hz)"); axes[1].legend()
axes[1].set_title("f-I curve: a threshold, then a rising rate")
plt.tight_layout(); plt.show()
print("Below threshold the neuron is silent; above it the rate rises towards a ceiling of 1 / refractory period"
      "\n(500 Hz here), approached only for very strong input."
      "\nInformation is carried by when and how often spikes occur, and computation happens only at spikes.")
```

2. Spike-timing-dependent plasticity: plot the STDP window, then let a neuron with 100 inputs learn, without labels, which inputs fire in a repeating pattern.
```python
import numpy as np
import matplotlib.pyplot as plt

# Spike-timing-dependent plasticity (STDP): a synapse strengthens when the input spike comes just BEFORE
# the output spike (it helped cause it) and weakens when it comes just after.
A_plus, A_minus, tau_plus, tau_minus = 0.010, 0.015, 20e-3, 20e-3    # depression slightly stronger:
# without that, inputs that fire at random also drift upwards and the neuron learns nothing selective

def stdp_window(dt_post_minus_pre):
    d = dt_post_minus_pre
    return np.where(d > 0, A_plus * np.exp(-d / tau_plus), -A_minus * np.exp(d / tau_minus))

# A neuron with 100 input synapses. Inputs 0-19 fire together in a repeating pattern that drives the
# neuron; inputs 20-99 fire at random. Online STDP with exponentially decaying spike traces.
rng = np.random.default_rng(1)
dt, T, n_in = 1e-3, 60.0, 100
w = np.full(n_in, 0.5)
tau_m, V, V_th = 10e-3, 0.0, 15.0
x_pre, x_post = np.zeros(n_in), 0.0                       # traces of recent pre- and postsynaptic spikes
w_history = []
for step in range(int(T / dt)):
    t = step * dt
    pre = rng.uniform(size=n_in) < 10 * dt                 # 10 Hz background activity on every input
    if (t % 0.1) < dt:                                     # every 100 ms the first 20 inputs fire together
        pre[:20] = True
    V += (-V / tau_m) * dt + w @ pre
    post = V >= V_th
    if post: V = 0.0
    x_pre = x_pre * np.exp(-dt / tau_plus) + pre          # includes this step's input spikes
    x_post = x_post * np.exp(-dt / tau_minus)               # output trace from BEFORE this step
    w -= A_minus * x_post * pre                            # depress inputs arriving after earlier outputs
    if post:
        w += A_plus * x_pre                                # potentiate inputs that fired before (or with) it
        x_post += 1
    w = np.clip(w, 0, 1)
    if step % 1000 == 0: w_history.append(w.copy())
w_history = np.array(w_history)
print(f"mean weight of the 20 patterned inputs: {w[:20].mean():.2f};  of the 80 random inputs: {w[20:].mean():.2f}")

fig, axes = plt.subplots(1, 2, figsize=(13, 4))
d = np.linspace(-0.1, 0.1, 400)
axes[0].plot(d * 1000, stdp_window(d), color='#3498db'); axes[0].axhline(0, color='k', linewidth=0.5)
axes[0].set_xlabel("t_post - t_pre (ms)"); axes[0].set_ylabel("weight change"); axes[0].set_title("STDP window")
axes[1].plot(w_history[:, :20].mean(1), color='#e74c3c', label="patterned inputs")
axes[1].plot(w_history[:, 20:].mean(1), color='#95a5a6', label="random inputs")
axes[1].set_xlabel("time (s)"); axes[1].set_ylabel("mean weight"); axes[1].legend()
axes[1].set_title("The neuron learns which inputs predict its firing")
plt.tight_layout(); plt.show()
print("No labels and no gradients: a purely local rule, using only the timing of spikes on each side of a"
      "\nsynapse, makes the neuron select the inputs that reliably fire together. That locality is what makes"
      "\non-chip learning cheap in neuromorphic hardware, and also what limits how much it can learn on its own.")
```

3. Train a spiking neural network with surrogate gradients and backpropagation through time, written out by hand: population-coded input spikes, a hidden layer of LIF neurons, and a leaky readout.
```python
import numpy as np
import matplotlib.pyplot as plt

# Training a spiking network with surrogate gradients, written out by hand.
rng = np.random.default_rng(2)
def moons(n):
    t = rng.uniform(0, np.pi, n); lab = rng.integers(0, 2, n)
    X = np.where(lab[:, None] == 0, np.c_[np.cos(t), np.sin(t)], np.c_[1 - np.cos(t), 0.5 - np.sin(t)])
    return X + rng.normal(0, 0.1, (n, 2)), lab
X, y = moons(600); Xt, yt = moons(600)

# Input encoding: each feature drives 10 neurons with Gaussian receptive fields; their firing
# probability per time step is the input "rate" (Poisson-like spike trains).
T, n_rf = 25, 10
centres = np.linspace(-1.2, 2.2, n_rf)
def encode(X):
    rates = np.exp(-((X[:, :, None] - centres) ** 2) / (2 * 0.25 ** 2)).reshape(len(X), -1)   # (B, 20)
    return (rng.uniform(size=(T,) + rates.shape) < 0.6 * rates).astype(float)                 # (T, B, 20)

n_in, n_hid, n_out = 2 * n_rf, 40, 2
beta, beta_out, theta = 0.85, 0.9, 1.0
W1 = rng.normal(0, 0.5, (n_in, n_hid)); W2 = rng.normal(0, 0.3, (n_hid, n_out))

def surrogate(v, k=5.0):
    """Derivative used in place of the spike's true derivative (a Dirac delta): a smooth bump at threshold."""
    return 1.0 / (1.0 + k * np.abs(v - theta)) ** 2

def forward(S_in):
    B = S_in.shape[1]
    v_h = np.zeros((B, n_hid)); v_o = np.zeros((B, n_out)); s_h = np.zeros((B, n_hid))
    V_h, S_h, V_o = [], [], []
    for t in range(T):
        v_h = beta * v_h + S_in[t] @ W1 - theta * s_h          # leaky integration with soft reset
        s_h = (v_h >= theta).astype(float)                     # spike: a step function
        v_o = beta_out * v_o + s_h @ W2                         # non-spiking leaky readout
        V_h.append(v_h); S_h.append(s_h); V_o.append(v_o)
    logits = np.mean(V_o, 0)
    return logits, np.array(V_h), np.array(S_h)

def train_step(S_in, y, lr, state):
    global W1, W2
    logits, V_h, S_h = forward(S_in)
    p = np.exp(logits - logits.max(1, keepdims=True)); p /= p.sum(1, keepdims=True)
    B = len(y)
    d_logits = (p - np.eye(n_out)[y]) / B                       # cross-entropy gradient
    # logits = mean_t v_o[t], v_o[t] = beta_out v_o[t-1] + s_h[t] W2  ->  each s_h[t] reaches the logits
    # through all later readout steps, with weight sum_{tau >= t} beta_out^(tau - t) / T
    coef = np.array([np.sum(beta_out ** np.arange(T - t)) / T for t in range(T)])
    dW2 = np.einsum("t,tbh,bo->ho", coef, S_h, d_logits)
    d_s = coef[:, None, None] * (d_logits @ W2.T)[None]          # dL/ds_h[t]
    dW1 = np.zeros_like(W1); d_v_next = np.zeros_like(V_h[0])
    for t in reversed(range(T)):                                 # backpropagation through time
        d_v = d_s[t] * surrogate(V_h[t]) + beta * d_v_next       # (the reset path is treated as constant)
        dW1 += S_in[t].T @ d_v
        d_v_next = d_v
    for name, W, g in [("W1", W1, dW1), ("W2", W2, dW2)]:       # Adam
        m, v = state.setdefault(name, [0 * W, 0 * W])
        m[:] = 0.9 * m + 0.1 * g; v[:] = 0.999 * v + 0.001 * g ** 2
        W -= lr * m / (np.sqrt(v) + 1e-8)
    return -np.mean(np.log(p[np.arange(B), y] + 1e-12))

state, losses = {}, []
for epoch in range(40):
    idx = rng.permutation(len(X))
    for b in range(0, len(X), 50):
        batch = idx[b:b + 50]
        losses.append(train_step(encode(X[batch]), y[batch], 0.01, state))
logits, _, S_h = forward(encode(Xt))
acc = np.mean(logits.argmax(1) == yt)
rate = S_h.mean()
print(f"training loss {np.mean(losses[:12]):.3f} -> {np.mean(losses[-12:]):.3f}; test accuracy {acc:.3f}")
print(f"hidden neurons spike on {rate:.1%} of time steps: activity is sparse, so most synapses do no work")

plt.figure(figsize=(8, 3.5)); plt.plot(losses, color='#3498db'); plt.xlabel("update"); plt.ylabel("loss")
plt.title("Spiking network trained with surrogate gradients"); plt.show()
print("The forward pass uses real spikes; only the backward pass pretends the step function is smooth."
      "\nThis trick (Neftci, Mostafa and Zenke, 2019) is how most competitive spiking networks are trained.")
```

4. Energy accounting: when do sparse spikes beat dense multiply-accumulates, and how much does it matter where the weights are stored?
```python
import numpy as np

# Energy accounting, with the widely quoted 45 nm figures (Horowitz, 2014), in picojoules:
E_MULT, E_ADD = 3.7, 0.9               # 32-bit float multiply and add
E_MAC = E_MULT + E_ADD                  # a conventional network's multiply-accumulate
E_AC = E_ADD                            # a spiking synapse: a spike is 1, so the "multiply" disappears
E_SRAM, E_DRAM = 5.0, 640.0             # reading 32 bits from small on-chip SRAM vs off-chip DRAM (approx.)

# A layer of 1000 inputs x 1000 outputs, evaluated once by an ANN, or over T time steps by an SNN
n_in = n_out = 1000
synapses = n_in * n_out
ann_compute = synapses * E_MAC

print("compute energy only (arithmetic):")
print(f"  ANN: {ann_compute / 1e6:6.2f} microjoules per inference")
print("  SNN, spike probability per input per time step p, over T steps:")
print("     p    |  T=4   |  T=16  |  T=64   (microjoules; below the ANN figure = cheaper)")
for p in [0.01, 0.05, 0.1, 0.3]:
    row = [synapses * p * T * E_AC + n_out * T * E_MAC for T in [4, 16, 64]]   # synaptic ACs + membrane updates
    print(f"   {p:4.2f}  | " + " | ".join(f"{e / 1e6:6.2f}" for e in row))
breakeven = E_MAC / E_AC
print(f"  break-even: the SNN wins on arithmetic only if p x T < {breakeven:.1f} (spikes per input per inference)")

print("\nnow add the cost of fetching each weight when it is used:")
for where, E_mem in [("weights in off-chip DRAM", E_DRAM), ("weights in local on-chip SRAM", E_SRAM)]:
    ann = synapses * (E_MAC + E_mem)                         # every weight fetched once per inference
    snn = synapses * 0.05 * 16 * (E_AC + E_mem)              # fetched for every spike that uses it (p=0.05, T=16)
    print(f"  {where:32s} ANN {ann / 1e6:8.1f} uJ   SNN (p=0.05, T=16) {snn / 1e6:8.1f} uJ")
print("\nMoving data costs far more than arithmetic. Spiking networks save energy when activity is sparse, the"
      "\nnumber of time steps is small, and weights live next to the neurons that use them, which is exactly"
      "\nwhat neuromorphic chips are built for. GPUs, built for dense matrix arithmetic, gain little from sparse"
      "\nspikes, so on a GPU the same SNN is usually slower and costlier than the equivalent ANN.")
```

5. Simulate an event camera watching a bar sweep across a textured scene, and compare its data volume and timing with frame-based cameras.
```python
import numpy as np
import matplotlib.pyplot as plt

# An event camera (dynamic vision sensor) has no frames. Each pixel independently reports an "event"
# (x, y, time, polarity) whenever its log-brightness changes by more than a contrast threshold C.
H = W = 64
dt = 1e-4                                       # simulate the scene at 10,000 steps per second
duration = 0.2
C = 0.15
yy, xx = np.mgrid[:H, :W]

def scene(t):
    """A bright bar sweeping across a static, textured background."""
    background = 0.3 + 0.1 * np.sin(xx / 5.0) * np.cos(yy / 7.0)
    bar_x = 5 + 250 * t                           # 250 pixels per second
    return background + 0.6 * (np.abs(xx - bar_x) < 2)

log_ref = np.log(scene(0.0))                     # brightness at each pixel's last event
events = []
for k in range(1, int(duration / dt)):
    t = k * dt
    L = np.log(scene(t))
    diff = L - log_ref
    fired = np.abs(diff) >= C
    ys, xs = np.nonzero(fired)
    for y_, x_ in zip(ys, xs):
        events.append((x_, y_, t, 1 if diff[y_, x_] > 0 else -1))
    log_ref[fired] = L[fired]
events = np.array(events)
frames_30fps = int(duration * 30) * H * W
print(f"{len(events):,} events in {duration * 1000:.0f} ms, versus {frames_30fps:,} pixel readings for a 30 fps camera"
      f" and {int(duration * 1000) * H * W:,} for a 1000 fps camera")
ahead = np.sum(events[:, 0] > 5 + 250 * events[:, 2] + 3)            # pixels the bar has not reached yet
print(f"events from parts of the scene the bar had not yet reached: {ahead} (unchanging pixels stay silent)")
print(f"this simulation timestamps events to {dt * 1e6:.0f} microseconds; real sensors resolve microseconds")

fig, axes = plt.subplots(1, 2, figsize=(12, 4.5))
```
