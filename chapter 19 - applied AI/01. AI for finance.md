# AI for Finance

*Finance was an early adopter of statistical modelling and remains one of the hardest places to apply machine learning well: the data are noisy, non-stationary and shaped by competitors who adapt to anything that works. This file covers the statistical character of financial data, return and volatility forecasting, factor models and machine learning for asset pricing, backtesting and its many traps, portfolio construction, execution and market microstructure, risk measurement, credit scoring, fraud and anti-money-laundering, language models for finance, alternative data, and model risk management*

- Machine learning in finance spans two very different worlds. In **operational** problems (credit decisions, fraud detection, document processing, customer service) the patterns are stable enough that standard methods work well, and the main difficulties are imbalance, regulation and explanation. In **markets** (predicting prices, building portfolios, trading) the signal is tiny, the noise is enormous, and every pattern that becomes known tends to be traded away. Methods that are routine elsewhere in this book fail quietly there, so this file spends as much time on how to avoid fooling yourself as on the models.

## The Character of Financial Data

- Prices themselves are non-stationary (chapter 06's time series file), so models work with **returns**: the simple return $R_t = P_t / P_{t-1} - 1$ or the **log return** $r_t = \ln(P_t / P_{t-1})$, which adds up over time and is approximately equal to the simple return for small moves.

- Returns share a set of **stylised facts**, observed across assets, markets and decades (Cont, 2001):
    - **Little linear predictability**: the autocorrelation of daily returns is close to zero. If yesterday's return predicted today's, traders would exploit it until it did not.
    - **Heavy tails**: extreme moves are far more common than a normal distribution allows. Kurtosis well above 3 is typical, and "five-sigma" days happen every few years instead of once in millions of years.
    - **Volatility clustering**: large moves follow large moves. The *size* of returns is strongly autocorrelated even though their *sign* is not.
    - **Leverage effect**: volatility tends to rise more after falls than after rises.
    - **Non-stationarity and regimes**: relationships change with monetary policy, technology, regulation and crises.

- **GARCH** models (Engle, 1982; Bollerslev, 1986) capture volatility clustering by letting today's variance depend on yesterday's squared return and yesterday's variance:

$$\sigma_t^2 = \omega + \alpha\, r_{t-1}^2 + \beta\, \sigma_{t-1}^2$$

- $\alpha$ measures how strongly shocks raise volatility and $\alpha + \beta$ how persistent volatility is (typically above 0.95 for daily data). GARCH is fitted by maximum likelihood and remains the standard baseline for volatility forecasting. The first coding task simulates it, shows the stylised facts, and recovers the parameters. Note the asymmetry: volatility is quite predictable, returns hardly at all.

- Financial data also have unusual practical problems: **survivorship bias** (datasets of today's companies omit those that went bankrupt, flattering any strategy tested on them), **look-ahead bias** (using information before it was available, including later-revised economic statistics), corporate actions (splits, dividends, mergers), and differing time zones and trading hours.

## Predicting Returns: Factors and Machine Learning

- **Factor models** explain the cross-section of returns (why some assets earn more than others) by exposures to common factors. The **CAPM** (Sharpe, 1964) uses one factor, the market. Fama and French added size and value (1993) and later profitability and investment; momentum is another long-studied factor. A stock's return is modelled as $r_i = \alpha_i + \sum_k \beta_{ik} f_k + \varepsilon_i$, and a strategy only shows skill if it earns **alpha** beyond what its factor exposures explain.

- **Machine learning for asset pricing.** Gu, Kelly and Xiu (2020) compared many methods for predicting individual stock returns from hundreds of characteristics, and found that trees and neural networks, by capturing non-linear interactions, predicted best, in some cases doubling the investment performance of leading regression-based strategies, with the most useful signals concentrated in a few robust predictors (momentum, liquidity, volatility). The predictive $R^2$ was still well under 1% per month. That is typical: in markets a tiny edge, applied across many assets and many periods, is the whole game.

- **Why markets are hard for ML:**
    - **Signal-to-noise** is extremely low, so models overfit easily and need strong regularisation.
    - **Adaptation and decay**: once a pattern is published or widely traded, it weakens. Studies of published return predictors find their returns fall substantially after publication.
    - **Non-stationarity**: a model trained on a calm decade meets a crisis.
    - **Data are limited** in the dimension that matters: there are only so many independent years, recessions or rate cycles.

- **Labelling** for supervised learning needs care. Fixed-horizon returns ignore the path; the **triple-barrier method** (López de Prado, 2018) labels each event by which comes first: a profit target, a stop loss or a time limit. **Meta-labelling** trains a second model to decide whether to act on a primary model's signal, and how much to bet, which separates direction from confidence.

## Backtesting and Its Traps

- A **backtest** simulates how a strategy would have performed on historical data. It is the main evidence for a strategy, and it is easy to get wrong in ways that inflate results:
    - **Look-ahead bias**: using any information not available at the decision time. In the fifth coding task, trading a moving-average signal at the same day's close, which already includes the day's move, turns a worthless rule into a Sharpe ratio above 5. The fix is to compute the signal from data up to time $t$ and apply it to returns from $t$ to $t + 1$.
    - **Transaction costs and market impact**: commissions, bid-ask spreads and the price moving against large orders can erase a high-turnover strategy's edge.
    - **Survivorship and selection bias** in the asset universe.
    - **Leakage in cross-validation**: financial labels often span several days, so a randomly split training sample overlaps the test period. **Purged** cross-validation removes training samples whose label windows overlap the test fold, and an **embargo** drops a further buffer after it, the financial version of the time-series splits in chapter 06's evaluation file.

- **Backtest overfitting** is the most insidious problem. Try enough variants (indicators, parameters, universes, holding periods) and one will look excellent by chance. In the third coding task, choosing the best of 526 moving-average rules on random-walk prices, where no rule has any edge, gives an in-sample Sharpe ratio around 0.8 on average and up to 1.4, which then disappears out of sample. The expected maximum of $N$ independent zero-skill Sharpe ratios grows roughly like $\sqrt{2 \ln N}$ standard errors.

- Defences: record and report the number of trials; compare the best result with what the best of that many zero-skill strategies would achieve (the **deflated Sharpe ratio**, Bailey and López de Prado, 2014); demand stronger statistical evidence for strategies found by search (a $t$-statistic above 3 has been proposed for factor research); hold out data that are never used for development; and prefer strategies with a clear economic rationale, which are less likely to be artefacts.

## Portfolio Construction

- **Mean-variance optimisation** (Markowitz, 1952) chooses weights $w$ to trade expected return against risk:

$$\max_w\; w^\top \mu - \frac{\lambda}{2}\, w^\top \Sigma\, w$$

- With expected returns $\mu$ and covariance $\Sigma$, the solution is proportional to $\Sigma^{-1}\mu$, and varying $\lambda$ traces the **efficient frontier**. The theory is elegant; in practice it is an **error maximiser**. Expected returns are estimated with huge error (the standard error of a mean return over one year is about as large as the mean itself), and the optimiser puts large weights exactly where the estimation errors are most favourable. In the second coding task the "optimal" portfolio promises a Sharpe ratio above 6 in-sample and delivers less than simple equal weighting out of sample, echoing DeMiguel, Garlappi and Uppal (2009), who found that the naive $1/N$ portfolio is hard to beat with estimated inputs.

- Practical remedies:
    - **Avoid estimating expected returns**: the **minimum-variance** portfolio uses only $\Sigma$, which is estimated much more reliably, and does well in the coding task. **Risk parity** sets weights so each asset contributes equally to total risk.
    - **Shrink the covariance**: the sample covariance of many assets is noisy and nearly singular. **Ledoit-Wolf shrinkage** (2004) blends it with a structured target such as a scaled identity, choosing the blend to minimise expected error. Factor models give structured covariances too.
    - **Black-Litterman** (1992) starts from the returns implied by market equilibrium and moves them towards the investor's views in proportion to their stated confidence, a Bayesian approach (chapter 05) that produces far more stable portfolios.
    - **Constraints** (no short positions, position limits, turnover limits) act as regularisation.

- The **Kelly criterion** sizes bets to maximise long-run growth: for a single bet, stake the fraction $f^* = \mu / \sigma^2$ of wealth in the continuous approximation. Full Kelly is very volatile and sensitive to errors in $\mu$, so practitioners use a fraction of it.

- **Reinforcement learning** (chapter 06, file 04) has been applied to portfolio management and trading, but results are fragile: the environment is non-stationary, simulators cannot reproduce how the market responds to your own trades, and the reward is very noisy. It has been more successful in narrower problems with good simulators, such as order execution and market making.

## Execution and Market Microstructure

- Deciding *what* to hold is half the problem; buying or selling it without moving the price is the other. Modern markets run on **limit order books**: lists of buy orders (bids) and sell orders (asks) at each price. A market order crosses the **bid-ask spread** and consumes liquidity; a large order walks up the book and moves the price.

- **Market impact** grows with order size, empirically roughly with the square root of the order's size relative to daily volume (the "square-root law"). Execution algorithms split a large order into many small ones:
    - **TWAP** (time-weighted average price): equal slices at regular intervals.
    - **VWAP** (volume-weighted average price): slices proportional to the expected volume profile over the day, which is usually U-shaped, heavy at the open and close.
    - **Implementation shortfall** strategies balance impact cost (trading fast) against the risk of the price drifting away (trading slowly). The Almgren-Chriss model (2000) solves this trade-off in closed form for a simple impact model.

- ML is used to forecast short-term volume, volatility and order flow, to choose order types and venues, and, with reinforcement learning, to learn execution policies in high-fidelity simulators. **Market making** (continuously quoting bids and asks, earning the spread while managing inventory risk) is another active area for RL.

## Risk Measurement

- **Value at Risk (VaR)** at level $\alpha$ is the loss that will not be exceeded with probability $1 - \alpha$ over a given horizon: "the one-day 99% VaR is 2 million" means a loss bigger than 2 million is expected on about 1 day in 100. Three classic estimates:
    - **Parametric (variance-covariance)**: assume normal returns, so VaR $\approx z_{1-\alpha}\, \sigma$. Simple and badly wrong in the tails.
    - **Historical simulation**: the empirical quantile of past returns. Captures fat tails but reacts slowly to changing volatility.
    - **Monte Carlo**: simulate from a fitted model (often with GARCH volatility and heavy-tailed shocks), needed for complex portfolios with options.

- **Expected shortfall (ES)**, also called conditional VaR, is the average loss *given* that the VaR is exceeded. VaR says nothing about how bad the bad days are; ES does, and unlike VaR it is subadditive (diversification never increases it). Banking regulation under the Basel Committee's market risk rules (the Fundamental Review of the Trading Book) moved from 99% VaR to 97.5% ES for this reason.

- **Backtesting VaR**: count the days the realised loss exceeded the VaR. The **Kupiec test** checks whether the exceedance rate matches the promised $\alpha$; the **Christoffersen test** checks whether exceedances are independent rather than clustered. In the fourth coding task, normal VaR fails the count test on fat-tailed data; historical VaR passes it but its breaches cluster in turbulent periods; scaling historical returns by current volatility ("filtered historical simulation") keeps the count right and makes breaches nearly independent.

- **Stress testing** complements statistical measures: revalue the portfolio under historical crises (2008, March 2020) and hypothetical scenarios. ML helps with scenario generation and with fast approximate revaluation of complex portfolios, replacing slow pricing models with learned surrogates.

## Credit Scoring

- **Credit risk** models estimate the **probability of default (PD)**, the **loss given default (LGD)** and the **exposure at default (EAD)**; expected loss is their product, $\text{EL} = \text{PD} \times \text{LGD} \times \text{EAD}$. PD models are classifiers, and they are among the most heavily regulated models in existence.

- The traditional **scorecard** is a logistic regression on binned features, each bin encoded by its **weight of evidence** $\text{WoE} = \ln(\text{share of goods} / \text{share of bads})$, scaled into points that add up to a score. It is transparent, monotone and easy to explain. Gradient-boosted models (chapter 06, file 06) are usually more accurate, especially with richer data, and are increasingly used with **monotonic constraints** and SHAP-based reason codes (file 13) to meet explanation requirements.

- Regulation shapes everything: US lenders must give applicants the principal reasons for a denial (adverse action notices); fair lending law prohibits discrimination and disparate impact (the fairness file); the EU AI Act classifies creditworthiness assessment as high-risk. **Reject inference** is a further subtlety: outcomes are only observed for applicants who were approved, so training data are a biased sample of the applicant population (a selection problem, see the causal inference file).

## Fraud and Anti-Money-Laundering

- **Card and payment fraud** detection is a real-time, extremely imbalanced classification problem with delayed and partial labels (chargebacks arrive weeks later), adversaries who adapt, and strict latency budgets. Chapter 18 works through the system design; the model side draws on chapter 06's gradient boosting, evaluation (precision-recall, cost-based thresholds) and anomaly detection files. The most powerful features are behavioural aggregates computed point-in-time (spend relative to this customer's usual pattern, velocity of transactions, device and merchant history).

- **Anti-money-laundering (AML)** monitoring has a different character: laundering is rare, labels are scarce and uncertain (a suspicious activity report is not proof), and traditional rule-based systems produce overwhelming numbers of false alerts. **Graph methods** are central, because laundering is a network phenomenon: chains and cycles of transfers, mule accounts, shared devices and addresses. Graph features and graph neural networks (chapter 12) on transaction networks help surface rings of accounts that look innocent individually.

## Language Models and Alternative Data

- **Text** is a major source of information: news, earnings call transcripts, regulatory filings, analyst reports, central bank statements. Classic approaches used finance-specific sentiment dictionaries, since general-purpose ones misread financial language ("liability" and "tax" are not negative in a 10-K). Domain-adapted models such as **FinBERT** improved sentiment classification, and large language models now extract structured data from filings, summarise calls, answer questions over documents (retrieval-augmented generation, chapter 07), and support analysts. Bloomberg trained a 50-billion-parameter finance-specialised model (BloombergGPT, 2023), though strong general models with retrieval have since proven competitive on many finance tasks. Hallucination and numerical errors are serious risks when outputs feed decisions; outputs must be grounded in and checked against the source documents.

- **Alternative data** goes beyond prices and filings: satellite images of car parks and oil tanks, ship and flight tracking, anonymised card-transaction panels, web traffic, app downloads, job postings. Many such datasets come with computer vision or NLP pipelines attached (chapters 07 and 08). The challenges are short histories (hard to backtest), coverage that changes over time, and legal questions about privacy, terms of service and material non-public information.

## Model Risk Management

- Banks are required to manage **model risk**, the risk of losses from models that are wrong or misused. US supervisory guidance (SR 11-7, 2011) set the template many institutions follow worldwide: independent validation, documentation of assumptions and limitations, ongoing performance monitoring, and governance over who can change a model. Machine learning models fit into this framework but strain it: they need explanation methods, stability analysis, fairness testing and drift monitoring (the interpretability, fairness and evaluation files), and their behaviour under stress must be understood before they are trusted with capital or customers.

1. The stylised facts of returns: simulate a GARCH(1,1) process, compare its tails and autocorrelations with Gaussian returns, and recover its parameters by maximum likelihood.
```python
import numpy as np
import matplotlib.pyplot as plt
from scipy.optimize import minimize
from math import erf

# GARCH(1,1): today's variance depends on yesterday's squared return and yesterday's variance.
#   r_t = sigma_t * z_t,   sigma_t^2 = omega + alpha * r_{t-1}^2 + beta * sigma_{t-1}^2
rng = np.random.default_rng(0)
n, omega, alpha, beta = 5000, 2e-6, 0.09, 0.90
r, s2 = np.zeros(n), np.zeros(n)
s2[0] = omega / (1 - alpha - beta)
for t in range(1, n):
    s2[t] = omega + alpha * r[t - 1] ** 2 + beta * s2[t - 1]
    r[t] = np.sqrt(s2[t]) * rng.standard_normal()
gauss = rng.normal(0, r.std(), n)                         # same volatility, no clustering

def acf(x, lags):
    x = x - x.mean()
    return np.array([x[:-k] @ x[k:] / (x @ x) for k in range(1, lags + 1)])
kurt = lambda x: np.mean((x - x.mean()) ** 4) / x.var() ** 2
for name, x in [("GARCH returns", r), ("Gaussian returns", gauss)]:
    print(f"{name:17s} kurtosis {kurt(x):5.2f} (normal = 3)   ACF of returns lag 1: {acf(x, 1)[0]:+.3f}   "
          f"ACF of |returns| lag 1, 10: {acf(np.abs(x), 10)[[0, 9]].round(3)}")
z_max = np.abs(r).max() / r.std()
expected = n * (1 + erf(-z_max / np.sqrt(2)))             # n * P(|Z| > z_max) for a normal Z
print(f"largest daily move: {z_max:.1f} standard deviations; a normal model expects {expected:.1e} such days in {n}")

# Fit GARCH(1,1) by maximum likelihood
def neg_loglik(p, r):
    w, a, b = p
    if w <= 0 or a < 0 or b < 0 or a + b >= 1: return 1e10
    s2 = np.empty_like(r); s2[0] = r.var()
    for t in range(1, len(r)):
        s2[t] = w + a * r[t - 1] ** 2 + b * s2[t - 1]
    return 0.5 * np.sum(np.log(s2) + r ** 2 / s2)
fit = minimize(neg_loglik, x0=[1e-6, 0.05, 0.8], args=(r,), method="Nelder-Mead",
               options={"xatol": 1e-9, "fatol": 1e-6, "maxiter": 4000})
print(f"\nfitted omega {fit.x[0]:.1e}, alpha {fit.x[1]:.3f}, beta {fit.x[2]:.3f}   "
      f"(true {omega:.0e}, {alpha}, {beta}); persistence alpha + beta = {fit.x[1] + fit.x[2]:.3f}")

fig, axes = plt.subplots(1, 2, figsize=(13, 4))
axes[0].plot(r, color='#3498db', linewidth=0.5); axes[0].set_title("GARCH returns: calm and turbulent periods")
axes[1].bar(range(1, 31), acf(np.abs(r), 30), color='#e74c3c', label="|returns|")
axes[1].bar(range(1, 31), acf(r, 30), color='#3498db', alpha=0.7, label="returns")
axes[1].set_title("Returns are uncorrelated; their size is not"); axes[1].legend()
plt.tight_layout(); plt.show()
```

2. Why mean-variance optimisation disappoints: estimate inputs from a year of data and compare the Sharpe ratio each portfolio promises with the one it delivers, for equal weights, maximum Sharpe, minimum variance, and minimum variance with a shrunk covariance.
```python
import numpy as np

# 30 assets whose true expected returns are all similar; the optimiser only sees noisy estimates of them.
rng = np.random.default_rng(1)
N, T_est, T_out = 30, 250, 250                            # one year to estimate, one year to invest
true_mu = rng.normal(0.0004, 0.0001, N)                    # daily expected returns, nearly identical
F = rng.normal(0, 1, (N, 3)) * 0.006                       # 3-factor covariance structure
true_cov = F @ F.T + np.diag(rng.uniform(0.0001, 0.0003, N))

def max_sharpe_weights(mu, cov):
    w = np.linalg.solve(cov, mu)                          # tangency portfolio direction
    return w / np.abs(w).sum()                            # normalise gross exposure to 1

def ledoit_wolf(X):
    """Shrink the sample covariance towards a scaled identity (Ledoit-Wolf 2004 estimate of the intensity)."""
    T, n = X.shape
    Xc = X - X.mean(0)
    S = Xc.T @ Xc / T
    m = np.trace(S) / n
    d2 = np.sum((S - m * np.eye(n)) ** 2)
    b2 = min(d2, np.sum([np.sum((np.outer(x, x) - S) ** 2) for x in Xc]) / T**2)
    return (b2 / d2) * m * np.eye(n) + (1 - b2 / d2) * S

sharpe = lambda w, mu, cov: (w @ mu) / np.sqrt(w @ cov @ w) * np.sqrt(252)
results = {k: [] for k in ["equal weight (1/N)", "max Sharpe, sample estimates",
                           "min variance, sample covariance", "min variance, shrunk covariance",
                           "max Sharpe, TRUE parameters (unattainable)"]}
in_sample = []
for trial in range(200):
    X = rng.multivariate_normal(true_mu, true_cov, T_est)
    mu_hat, cov_hat = X.mean(0), np.cov(X.T)
    weights = {
        "equal weight (1/N)": np.full(N, 1 / N),
        "max Sharpe, sample estimates": max_sharpe_weights(mu_hat, cov_hat),
        "min variance, sample covariance": max_sharpe_weights(np.ones(N), cov_hat),
        "min variance, shrunk covariance": max_sharpe_weights(np.ones(N), ledoit_wolf(X)),
        "max Sharpe, TRUE parameters (unattainable)": max_sharpe_weights(true_mu, true_cov),
    }
    in_sample.append(sharpe(weights["max Sharpe, sample estimates"], mu_hat, cov_hat))
    for k, w in weights.items():
        results[k].append(sharpe(w, true_mu, true_cov))      # the Sharpe ratio it will really deliver
print(f"max-Sharpe portfolio, Sharpe ratio it PROMISES in-sample: {np.mean(in_sample):.2f}")
print(f"\n{'strategy':44s} true annualised Sharpe (mean over 200 trials)")
for k, v in results.items():
    print(f"{k:44s} {np.mean(v):.2f}")
print("\nMean returns are estimated so poorly from a year of data that the 'optimal' portfolio is mostly fitting"
      "\nnoise: it promises a spectacular Sharpe ratio and delivers less than equal weighting. Covariances are"
      "\nestimated far better, so minimum-variance portfolios do well, and shrinkage helps a little more.")
```

3. Backtest overfitting: search 526 moving-average strategies on random-walk markets where no strategy has an edge, pick the best in-sample, and test it out of sample.
```python
import numpy as np

# Prices that are pure random walks: by construction, NO strategy has an edge.
rng = np.random.default_rng(2)
T = 2520                                                   # 10 years of daily returns
split = T // 2                                             # first 5 years to choose, last 5 to test

def ma_crossover(prices, returns, fast, slow, cost=0.0005):
    """Long when the fast moving average is above the slow one, short otherwise.
    The position is decided on today's close and earns TOMORROW's return: no look-ahead."""
    c = np.cumsum(np.r_[0, prices])
    fast_ma = (c[slow:] - c[slow - fast:-fast]) / fast
    slow_ma = (c[slow:] - c[:-slow]) / slow
    signal = np.r_[np.zeros(slow - 1), np.where(fast_ma > slow_ma, 1.0, -1.0)]
    position = np.r_[0, signal[:-1]]
    return position * returns - cost * np.abs(np.diff(np.r_[0, position]))

sharpe = lambda x: x.mean() / (x.std() + 1e-12) * np.sqrt(252)
configs = [(f, s) for f in range(2, 50, 2) for s in range(10, 250, 10) if f < s]

best_in, best_out, all_corr = [], [], []
for world in range(20):                                    # 20 independent random-walk markets
    returns = rng.normal(0.0, 0.01, T)
    prices = 100 * np.exp(np.cumsum(returns))
    ins, outs = [], []
    for f, s in configs:
        strat = ma_crossover(prices, returns, f, s)
        ins.append(sharpe(strat[:split])); outs.append(sharpe(strat[split:]))
    ins, outs = np.array(ins), np.array(outs)
    best_in.append(ins.max()); best_out.append(outs[np.argmax(ins)])
    all_corr.append(np.corrcoef(ins, outs)[0, 1])

print(f"{len(configs)} moving-average strategies, tested on 20 random-walk markets with zero edge")
print(f"best in-sample Sharpe ratio (mean over markets):   {np.mean(best_in):+.2f}   (range {min(best_in):+.2f} to {max(best_in):+.2f})")
print(f"the same strategies out of sample:                 {np.mean(best_out):+.2f}")
print(f"correlation of in- and out-of-sample Sharpe across strategies: {np.mean(all_corr):+.2f}")
print(f"\nluck benchmark: sqrt(2 ln N) / sqrt(years) = {np.sqrt(2 * np.log(len(configs))) / np.sqrt(split / 252):.2f}"
      " for N independent strategies (lower when they are correlated, as these are)")
print("A backtest is a multiple-testing problem. Report how many variants were tried, and judge the winner"
      "\nagainst what the best of that many zero-skill strategies would have achieved (the deflated Sharpe ratio).")
```

4. Value at Risk and expected shortfall on fat-tailed, volatility-clustered returns: compare normal, historical and volatility-filtered historical VaR with the Kupiec test and a measure of breach clustering.
```python
import numpy as np
from math import erf, sqrt, log

# Daily portfolio returns with fat tails (Student-t, 4 degrees of freedom) and volatility clustering (GARCH)
rng = np.random.default_rng(3)
n = 6000
r, s2 = np.zeros(n), np.full(n, 1e-4)
for t in range(1, n):
    s2[t] = 2e-6 + 0.08 * r[t - 1] ** 2 + 0.90 * s2[t - 1]
    r[t] = np.sqrt(s2[t]) * rng.standard_t(4) / np.sqrt(2)          # unit-variance t(4)

alpha, window = 0.01, 500                                          # 99% one-day VaR, 2-year lookback
z99 = 2.326
norm_cdf = lambda z: 0.5 * (1 + erf(z / sqrt(2)))
methods = {"normal (variance-covariance)": [], "historical simulation": [], "filtered (GARCH-scaled) historical": []}
es_hist, realised = [], []
for t in range(window, n):
    past = r[t - window:t]
    methods["normal (variance-covariance)"].append(-(past.mean() - z99 * past.std()))
    q = -np.quantile(past, alpha)
    methods["historical simulation"].append(q)
    # Filtered: standardise past returns by their volatility at the time, rescale by today's forecast volatility.
    # (The simulation's true GARCH variance stands in for a fitted GARCH forecast, as in the GARCH task above.)
    z = past / np.sqrt(s2[t - window:t])
    methods["filtered (GARCH-scaled) historical"].append(-np.quantile(z, alpha) * np.sqrt(s2[t]))
    es_hist.append(-past[past <= -q].mean())                       # expected shortfall beyond the VaR
    realised.append(r[t])
realised = np.array(realised)

def kupiec(exceed, n_obs, p):
    """Likelihood-ratio test that the exceedance rate equals p (chi-square, 1 dof; 3.84 = 5% critical value)."""
    x = exceed; ph = x / n_obs
    ll0 = (n_obs - x) * log(1 - p) + x * log(p)
    ll1 = (n_obs - x) * log(1 - ph) + x * log(ph) if 0 < x < n_obs else 0
    return -2 * (ll0 - ll1)

print(f"99% one-day VaR backtest over {len(realised)} days (expected exceedances: {alpha * len(realised):.0f})")
print(f"  {'method':36s} {'breaches':>8s}  {'Kupiec LR':>9s}         {'clustered':>9s}")
for name, var in methods.items():
    b = np.flatnonzero(realised < -np.array(var))
    lr = kupiec(len(b), len(realised), alpha)
    clustered = np.mean(np.diff(b) <= 10)                         # breaches within 10 days of the previous one
    print(f"  {name:36s} {len(b):8d}  {lr:9.2f} {'reject' if lr > 3.84 else 'pass  '}  {clustered:9.0%}")
print(f"  (if breaches were independent at a ~1.2% rate, about {1 - (1 - 0.0125) ** 10:.0%} would be clustered)")
hist_var = np.array(methods["historical simulation"])
breaches = realised < -hist_var
print(f"\nwhen historical VaR is breached, the average loss is {-realised[breaches].mean():.4f} versus"
      f" a VaR of {hist_var[breaches].mean():.4f}; expected shortfall predicted {np.mean(np.array(es_hist)[breaches]):.4f}")
print("The normal model underestimates fat tails and fails the count test. Historical simulation gets the count"
      "\nright but reacts slowly to changing volatility, so its breaches arrive in bunches during turbulent spells."
      "\nRescaling by current volatility keeps the count and makes breaches nearly independent. VaR says how"
      "\noften the line is crossed; expected shortfall says how bad things are beyond it.")
```

5. Look-ahead bias in one line: the same signal backtested with same-day and next-day returns.
```python
import numpy as np

# A random-walk market again: no strategy can truly have an edge.
rng = np.random.default_rng(5)
T = 2520
returns = rng.normal(0, 0.01, T)
prices = 100 * np.exp(np.cumsum(returns))
sharpe = lambda x: x.mean() / x.std() * np.sqrt(252)

# Signal: buy if today's price is above its 20-day average (computed from prices up to and including today)
ma20 = np.convolve(prices, np.ones(20) / 20, mode="full")[:T]
ma20[:19] = np.nan
signal = np.nan_to_num(np.where(prices > ma20, 1.0, -1.0))

# WRONG: earn today's return with a signal that already used today's closing price
leaky = signal * returns
# RIGHT: the signal from today's close earns tomorrow's return
honest = np.r_[0, signal[:-1]] * returns
print(f"same-day (look-ahead) backtest Sharpe ratio: {sharpe(leaky):5.2f}")
print(f"next-day (honest) backtest Sharpe ratio:     {sharpe(honest):5.2f}")
print("\nToday's return moved today's price, which moved the signal: the leaky version partly trades on the"
      "\nanswer. A one-line indexing slip turns a worthless rule into a 'great' strategy. Other forms of the same bug:"
      "\nusing revised economic data instead of what was published at the time, today's index members (survivorship"
      "\nbias), and fitting a scaler or model on the full history before backtesting.")
```
