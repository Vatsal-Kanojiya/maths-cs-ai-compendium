Smaller, Not Cheaper

The last part of Chapter 16 leaves the data centre. One vector loop runs on any width of machine; one shader runs on any vendor’s GPU; one model runs on a chip that costs a dollar. Each works the same way: write to the smallest machine you are guaranteed, and ask the real one what it has. The same two laws as parts 1 and 2 price every step.

This part covers source file 06 (RISC-V and embedded systems) and file 07 (Vulkan compute and cross-platform GPUs), and closes the chapter with its worked example, question bank, a map of all three parts and its own Appendix A. Part 2 §19 listed six calculations this part owes. They are paid in §02 (RISC-V’s vector loop), §07 (Vulkan subgroups as lanes), §08 (file 07’s reduction tree), §09 (its tiled matmul, priced), §04 (energy per FLOP) and §14 (the chapter map).

The headline is §04, and it comes from the source’s own table of a server GPU, a smartphone and a microcontroller. Divide each one’s compute by its power: 0.70, 0.50 and 1.00 picojoules per FLOP. Across a 700,000-fold range of power, the energy per operation moves by a factor of two, and the cheapest is the phone. The edge is smaller, not cheaper. Part 1’s cube law would have predicted the microcontroller at 4.6 femtojoules, 219 times less; part 1 §03 warned that the law ignores leakage, and the table shows how much that matters at the bottom.

The other exact result is §02. RISC-V’s vsetvl lets the hardware choose how many elements each pass of a loop handles, and even lets it split the last two passes evenly. Checked for every array length up to 3,000 at seven widths, the number of passes is always \(\lceil n/\text{VLMAX}\rceil\): part 1’s drilling head, with the spindle count read off the machine.

No RISC-V board, emulator or GPU was available. The source’s vector loop was compiled for RISC-V with clang and read; its three C++ tasks were compiled and run on the x86 build machine; all six GLSL shaders in file 07 were compiled to SPIR-V with glslang (its WebAssembly build). Hardware figures are the source’s or marked as reported. Checks are tagged [Ch16p3 sNN] in verify_claims.py.

RISC-V: an instruction set as an open standard

src 06. RISC-V ↗

An instruction set architecture (ISA) is the contract between software and a processor: the list of instructions, registers and memory rules that any chip of that family must honour. x86 and ARM are licensed contracts. RISC-V, started at Berkeley in 2010, is an open one: anyone may build a chip to it without a fee. It is modular. A small base (RV32I or RV64I) is extended by letters: M for multiply and divide, A for atomic operations, F and D for floating point, C for compressed instructions, V for vectors. A chip carries only the letters it needs, the way a part drawing calls up only the standards that apply to it.

The base has 32 general-purpose registers, x0 to x31, with x0 wired to zero; the source counts these correctly, where part 1 §09 caught it miscounting ARM’s ([Ch16p3 s01]). Instructions are a fixed 32 bits, with 16-bit forms in the C extension, and only loads and stores touch memory. The source’s “just 47 instructions” for the base is reported; the ratified base specification is reported to list 40, the difference being instructions since moved into separate extensions. Its gate counts (about 10,000 for a minimal core against 12,000 for an ARM Cortex-M0) and its list of adopters are reported too.

One loop for any width

src 06. RISC-V ↗

Debt 1 of 6. The V extension gives RISC-V vector registers whose width, VLEN, the hardware chooses: any power of two from 128 to 65,536 bits. Code is written without knowing it. The source’s vector addition is a strip-mining loop:

$$\texttt{vl} = \texttt{vsetvl}(n_{\text{left}}), \quad \text{process } \texttt{vl} \text{ elements}, \quad n_{\text{left}} \leftarrow n_{\text{left}} - \texttt{vl}, \quad \text{repeat while } n_{\text{left}} > 0 .$$

The program asks for \(n_{\text{left}}\) elements and the hardware answers with how many it will take this pass. The most it can take is

$$\text{VLMAX} = \frac{\text{VLEN} \times \text{LMUL}}{\text{SEW}},$$

where SEW is the element width in bits and LMUL the number of registers ganged together. For 32-bit floats and LMUL = 1 that is 4 lanes at VLEN 128 and 2,048 at VLEN 65,536. Compiled for RISC-V with clang, the source’s loop is 11 instructions per pass: vsetvli, two vector loads, one vector add, one vector store, and six to move pointers, count down and branch ([Ch16p3 s02]). At VLEN 128 that is 2.75 instructions per float; at 65,536, 0.0054. The binary is the same; only the number of passes changes.

The source says vsetvl returns \(\min(n, \text{VLMAX})\). The vector specification is reported to allow more: when \(n_{\text{left}}\) lies between VLMAX and \(2\,\text{VLMAX}\), the hardware may return anything from \(\lceil n_{\text{left}}/2 \rceil\) to VLMAX, so it can split the last two passes evenly instead of leaving a scrap for the last one. Simulated both ways for every \(n\) from 1 to 3,000 at seven values of VLMAX, the pass count is the same and equal to

$$\text{passes} = \left\lceil \frac{n}{\text{VLMAX}} \right\rceil ,$$

and every element is processed exactly once. For 1,000 floats at VLEN 512 that is 63 passes, the last holding 8 of 16 lanes (or two passes of 12 when balanced), with 99.2% of lane-passes doing work.

✓Identity: part 1’s drilling head, with the spindle count read off the machine

Part 1 §05 counted \(\lceil n/W \rceil\) strokes for \(n\) holes on a \(W\)-spindle head, with the spare drills of the last stroke removed. Part 1 §09 met SVE, where svwhilelt builds the mask for a head of unknown width, and part 2 §11 met the same mask in Triton. vsetvl goes one step further: there is no mask in the loop at all, because the machine tells the program how many spindles carry drills on each stroke. The stroke count is the same expression in all four. The balanced tail is the furnace operator’s rule of evening out the last two loads rather than running one full and one nearly empty: the number of loads is unchanged and neither is wasteful.

LMUL gangs registers. With LMUL = 8 one instruction covers eight registers’ worth of elements, and the 32 vector registers become 4 groups, as the source says: 32, 16, 8 and 4 groups at LMUL 1, 2, 4 and 8. It is ganging several heads on one slide: more holes per stroke, fewer separate heads to hold the work in progress.

!Where it breaks

A pass count is not a time. Each pass still has its fixed 11 instructions, and a wide machine is only as fast as its memory can feed it, which is part 1’s roofline again: a vector add does one FLOP per 12 bytes on any VLEN. Fewer registers per group at high LMUL also means fewer independent accumulators, which part 1 §08 showed is what keeps a chain of dependent operations busy. The loop is portable; its speed is not.
